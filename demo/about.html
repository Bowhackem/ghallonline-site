About this demo

This is a prototype of Seattle Bark District's operations and route-planning layer, built to show how the routing/assignment engine works. It is not connected to Time To Pet or any real SBD data.

What's real vs. simplified

The routing and scoring logic -- feasibility checks, travel-time-aware conflict detection, and the walker recommendation ranking -- is the exact same code as the real application, not a simplified stand-in. What's different is only how data gets in and how changes are saved: the real app reads/writes a local database and can sync from Time To Pet; this demo starts from a fixed synthetic dataset and keeps all changes in your browser tab.

The Bosco/Gary/Lindsey scenario on the Day Planner is the clearest example: Gary is geographically closer, but the system recommends Lindsey because Gary genuinely can't arrive on time -- the same "more than just nearest walker" behavior the real app has.
